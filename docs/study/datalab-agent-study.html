1큰 그림 — 세 곳이 나눠 맡는다

원본 파일은 서버로 가지 않는다

핵심 한 줄
서버는 "머리"만 있고 "손"이 없다. 데이터가 브라우저에 있으니, 서버는 도구를 직접 실행하지 못하고 멈춰서(interrupt) 브라우저에 일을 넘긴다.

왜 이렇게 나눴나:

  • 개인정보 원칙 — 엑셀 원본·결과 표를 서버 디스크에 남기지 않는다.
  • 서버 사양이 작다 — 계산은 사용자 PC 가 하고, 서버는 기다리기만 한다.
  • 망 구조 — 서버(개발망)는 Dify(업무망)에 못 닿아서 LLM_BASE_URL 게이트웨이를 직접 쓴다.

3LangGraph 핵심 개념

그래프 · 상태 · 체크포인터 · interrupt · Command

그래프와 상태

LangGraph 는 노드(함수)를 엣지로 이은 상태 기계다. 상태는 딕셔너리이고, 에이전트에서는 주로 messages 리스트다. create_agent 가 만드는 그래프는 두 노드짜리다.

[model] ──tool_calls 있음──▶ [tools] ──▶ [model] …
   │
   └─tool_calls 없음──▶ END

체크포인터 = 멈춘 그래프를 기억하는 곳

매 단계가 끝날 때 상태를 thread_id 별로 저장한다. 그래서 중간에 멈췄다가 다른 HTTP 요청에서 이어 갈 수 있다. 여기서는 메모리 전용 InMemorySaver — 결과 값에 개인정보가 섞일 수 있어 DB 에 두지 않는다.

interrupt() 와 Command(resume)

from langgraph.types import interrupt, Command

# 도구 안에서 — 여기서 그래프가 멈춘다
value = interrupt({"tool": "run_sql", "args": {...}})
return value   # 재개되면 resume 값이 여기로 들어온다

# 라우터에서 — 멈췄는지 확인
state = await agent.aget_state(config)
state.interrupts   # [Interrupt(id=..., value={...})]

# 브라우저 결과가 오면 — id 별로 값을 넘겨 재개
agent.astream(Command(resume={interrupt_id: 결과}), config)
함정 — 재개하면 그 노드(도구 함수)가 처음부터 다시 실행된다. interrupt() 앞에 부작용(DB 쓰기, 카운터 증가)을 두면 두 번 일어난다. 여기서는 SQL 1차 검사만 있어서 다시 돌아도 괜찮다.
왜 한 연결로 기다리지 않나?
브라우저가 SQL 을 몇 초~몇 분 돌릴 수 있다. 그동안 SSE 연결을 붙잡으면 프록시 타임아웃에 걸리고, 서버 자원도 묶인다. 멈춤 → 연결 닫기 → 새 POST 로 재개가 더 단단하다.

5미들웨어 — 루프에 끼우는 훅

목록 순서 = 바깥 → 안쪽

GuardMiddleware.awrap_model_call     ← 자리 잡기 · 예산 자르기 · 차단기 기록
  ModelRetryMiddleware               ← 일시 오류 재시도 (자리를 잡은 채로)
    GatewayChatModel                 ← 실제 HTTP
backend/app/agent/agent.py — GuardMiddleware 
class GuardMiddleware(AgentMiddleware):
    async def awrap_model_call(self, request, handler):
        ctx = request.runtime.context
        # 1) 예산 — 넘치면 오래된 도구 결과부터 비운다
        request = request.override(messages=trim_turn_messages(request.messages, budget))
        # 2) 격벽 — 자리가 날 때까지 기다림(대기 순번을 SSE 로)
        await gate.acquire(limit=..., queue_max=..., wait_sec=..., on_queued=...)
        ok = False
        try:
            response = await handler(request)   # ← 안쪽(재시도 → 모델) 실행
            ok = True
            return response
        finally:
            gate.release(limit)
            breaker.record(ok, ...)
wrap 패턴 읽는 법
handler(request) 앞 = 호출 전 처리, 뒤 = 호출 후 처리. Express/Koa 미들웨어의 next() 와 같은 모양이다.

훅 종류(1.x): before_model·after_model(상태 고치기), wrap_model_call·wrap_tool_call(감싸기), before_agent·after_agent. 비동기 버전은 앞에 a.

쓰지 않기로 한 것: SummarizationMiddleware(LLM 으로 요약 — 호출 늘고 숫자가 흐려짐), ShellToolMiddleware·FilesystemFileSearchMiddleware(서버 셸·파일 접근).

@tool
def run_sql(sql: str, title: str, runtime: ToolRuntime[AgentContext]) -> str:
    """DuckDB SQL 한 문장을 실행한다. … title 은 사용자에게 보일 쉬운 한국어 단계 이름."""
    reason = sql_block_reason(sql)        # INSTALL·ATTACH·COPY·SET … 1차 거름

    return _browser(runtime, "run_sql", {"sql": sql, "title": title[:60]})
  • 모델이 보는 것 = 함수 이름 + 인자 타입 + docstring. 그래서 docstring 을 사용 설명서처럼 쓴다.
  • runtime: ToolRuntime[…] 은 모델에게 안 보이는 주입 인자 — 대화 객체·결과 상한 같은 서버 정보를 runtime.context 로 꺼낸다.
  • Pydantic 모델(TermMapping)을 인자로 쓰면 스키마가 그대로 모델에게 전달된다.
도구어디서하는 일

9서비스 보호 — 이 기능만 늦추거나 멈춘다

사용자 한도가 아니라 안전판

  • 격벽(AgentGate) — 이 기능 전용 동시 모델 호출 수. 꽉 차면 대기열(순번을 SSE queued 로), 대기열도 차면 즉시 "잠시 후 다시". 상한을 실행 중에 바꿀 수 있게 세마포어 대신 카운터 + Future 대기열로 직접 만들었다. 자리는 넘겨준다(새 요청이 새치기 못 하게).
  • 회로 차단기(Breaker) — 최근 20건 중 오류율이 기준을 넘으면 새 질문만 잠시 거절, 쉬는 시간이 지나면 다시 받는다.
  • 기존 한도와 분리 — llm_slots·분당 호출을 같이 쓰면 이 기능이 몰릴 때 번역·요약까지 막힌다.
  • 긴급 스위치·상한 값 — 관리자 화면에서 재기동 없이(llmopts.AGENT_SPEC).
비동기 규칙 — uvicorn --workers 1 이라 동기 호출 하나가 서비스 전체를 멈춘다. LangChain 은 ainvoke·astream 만, 동기 _generate 는 일부러 예외를 던지게 했다.

수만 행이어도 보이는 줄만 그린다(TanStack Virtual). 스크롤 위치의 구간을 200행씩 LIMIT/OFFSET 으로 가져와 캐시(12장). 정렬은 머리글 클릭 → SQL. JS 에 전체 행 배열을 만들지 않는다.

작업 순서(session.ts)

진입 → DuckDB 열기(OPFS) → 바로 잠금
파일 → 워커 parse(SheetJS) → 점검 → 추천값으로 정리 → Arrow → insertIPC
나가기(pagehide·unmount) → DB 파일 삭제(핸들 해제 지연 때문에 재시도)

  • 모든 행·모든 시트를 훑는다(표본 아님). 화면이 멈추지 않게 Web Worker 에서.

12용어 맞추기 — 사람 말 ↔ 열·값

matchterms.ts · LLM 없음

  1. 열 이름 비슷함 — 공백·괄호·단위를 떼고 포함 관계 + 2글자 조각 겹침(Dice). 한국어는 Jaro-Winkler 가 잘 안 맞았다(판매금액↔매출액 0.72).
  2. 사내 동의어 표 — 매출↔판매금액, 본부↔사업부 … (글자가 전혀 다른 같은 뜻은 이것뿐)
  3. 값 안에서 찾기 — 글자 열마다 count(*) FILTER (WHERE col ILIKE '%서울%') 를 한 쿼리로.

후보가 둘 이상이거나 점수가 낮으면 프롬프트 규칙으로 반드시 ask_user. 확정되면 confirm_terms → 용어집 → 다음 질문엔 안 묻는다. 채팅에는 "이렇게 이해했어요: 매출 → 판매금액" 칩.

13단계 기록과 되돌리기

steps.ts — SQL 하나 = 단계 카드 하나

조회(SELECT·WITH)  → CREATE TABLE step_N AS <sql>     다음 단계가 이어 쓸 수 있다
수정(UPDATE·DELETE…) → 먼저 CREATE TABLE _vN_0 AS SELECT * FROM 대상
되돌리기(n)          → n 이후 단계를 거꾸로 복사본으로 덮기
  • 실패한 SQL 은 번호를 쓰지 않는다(카드 번호가 건너뛰지 않게). 만들어 둔 복사본도 치운다.
  • 되돌리기 지점은 최근 10개만, 조회 결과 표는 최근 20개만 — 브라우저 디스크 보호.
  • 되돌릴 수 없는 단계가 중간에 끼면 아무것도 건드리지 않고 거절.

15복습 — 눌러서 답 보기

Q1. 도구가 서버에서 실행되지 않는데 어떻게 LangGraph 루프가 이어지나?

도구 본문에서 interrupt() 로 그래프를 멈추고, 체크포인터가 상태를 기억한다. 브라우저 결과가 오면 Command(resume={id: 결과}) 로 재개하고, 그 값이 interrupt() 의 반환값이 된다.

Q2. 재개할 때 조심할 점은?

interrupt 가 있는 노드(도구 함수)가 처음부터 다시 실행된다. 그 앞에 부작용을 두면 안 된다.

Q3. 모델에게 안 보이는 도구 인자는?

runtime: ToolRuntime[AgentContext]. 실행 때 astream(..., context=…) 로 넣은 값이 주입된다.

Q4. 미들웨어 목록에서 GuardMiddleware 가 재시도보다 앞인 이유?

바깥이 먼저 실행된다. 격벽 자리를 잡은 채로 안쪽에서 재시도하게 해서, 재시도가 대기열을 새치기하지 않게 했다. 또 AgentBusy 는 바깥에서 나오므로 재시도 대상이 아니다.

Q5. 왜 질문마다 새 thread 인가?

SQL·도구 결과가 다음 질문의 컨텍스트로 넘어가지 않게(65k 한계). 남는 건 용어집·질문 원문·짧은 답, 그리고 브라우저가 매번 새로 만드는 상태 요약.

Q6. 도구 결과를 줄일 때 메시지를 지우지 않고 내용만 비우는 이유?

AI 메시지의 tool_call 과 ToolMessage 는 짝이 맞아야 한다. 짝이 깨지면 OpenAI 호환 서버가 400 을 낸다.

Q7. DuckDB 를 잠갔는데 새 파일은 어떻게 넣나?

파일 읽기(read_csv)는 막히지만 Arrow IPC 삽입은 된다. 워커가 Arrow 로 만들어 insertArrowFromIPCStream.

Q8. 사람에게 묻기(ask_user)는 어떻게 구현했나?

다른 브라우저 도구와 똑같이 interrupt. 브라우저가 Promise 를 선택 카드에 걸어 두고, 클릭 값이 tool-result 로 간다. 멈추기를 누르면 그 Promise 를 먼저 풀어 준다.

Q9. 이 기능이 몰리면 무엇이 멈추나?

이 기능만. 전용 격벽(대기열·거절)과 회로 차단기(새 질문만 잠시 거절), 전용 연결 풀. 기존 llm_slots·분당 한도는 공유하지 않는다.
